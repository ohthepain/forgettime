# Recorded bar training annotation

Choose **Annotate training attacks** in Recorded bar. Entry stops replay/capture and disarms Auto before opening the editor. Recording, source replacement and simulation are unavailable while editing; Close annotation offers Save, Discard and Stay for an unsaved draft. Save goes through Review & save and still requires the explicit Add/Overwrite action. Browser reload/tab close uses the browser's standard unsaved-work prompt; drafts are not recovery checkpoints.

1. **Correct attacks** seeds a new draft once from the review detector's full-source calculation. Existing saved labels (including reviewed silence) take precedence. Green markers are desired; dashed blue markers are calculated. Explicit Add mode permits taps, with movement rejected as a placement gesture. Select an attack to remove it or edit its exact source seconds. Nudge buttons and focused-marker arrow keys move one sample (Shift-arrow: 1 ms). The source-seconds field also adds an attack without a pointer. Attack lists are paged for keyboard/touch access.
2. **Mark uncertainty** adds nonoverlapping half-open source ranges, with editable start/end seconds and removal. Desired markers remain stored inside uncertainty, but appear subdued and are excluded by the authoritative scorer. Undo restores marker, range, reset and tempo edits, with up to 100 steps.
3. **Review & save** displays desired source times and uncertain ranges. Add/Overwrite explicitly confirms review of every attack, including outside uncertain regions; there is no separate checkbox. Partial bars remain inspectable/editable but cannot be submitted. Entirely uncertain examples can be stored for inspection; `trainingEligible` excludes them from optimization.

Training tempo is separate from the original take and future live tempo. Changes keep beat one and every underlying marker at its source frame, recutting the bar bounds. Markers outside the new bar remain in the draft, so expanding/undoing restores them; saved examples include only labels within the selected available bar. Tempo persists while navigating training bars. Changed bounds have a new identity and Add preserves the previously saved example. A known matching identity requires explicit Overwrite; an example added in another window is never silently overwritten.

Time zoom, navigation and height sliders affect display only. Audition reuses `AudioRegionPreview` for one-shot original PCM from the selected visible attack (or view start) to the visible endpoint. Stop/Escape, selection/view/settings changes, hiding, navigation and unmount release output. There is no microphone input, scoring, normalization or altered PCM in audition. Waveform geometry is shared with import inspection.

The controller (`src/audio/training-annotation.ts`) converts capture clocks to frame zero of the retained full source by subtracting `audio.startFrame`. It hashes and owns the full mono PCM, uses source/bar IDs and the atomic training repository, preserves existing recording-group assignments, and creates new groups as unassigned. Source audio is deduplicated by canonical checksum. Cropped/saved/captured material conservatively declares unavailable source-edge context; an ordinary complete decoded import declares its own beginning/end available. No discarded ancestor audio is invented. Matching stored source metadata wins.

Overwrite replaces only current annotations/review status under the loaded fingerprint. Quota, validation or concurrent-change failures preserve the draft and prior committed dataset. There is no annotation revision history, automatic export or upload. Original take PCM, settings, reference and analysis remain untouched. Calculation changes update the overlay only; Reset desired attacks from detections requires confirmation and can be undone. This UI currently uses the existing review detector; candidate profile adoption and the training-set inspector are separate issues.

## Verification

Controller tests cover source-clock conversion, tempo recuts/Undo, uncertainty validation, explicit reset, reviewed silence, full-source deduplication, overwrite, atomic failure retention, stale writes and partial rejection. Component tests exercise real fields/buttons, marker keyboard controls, explicit placement/movement suppression, ranges, detector changes, Save/Discard/Stay, failed save/retry and audition cleanup. Practice integration checks stop-before-entry and source-replacement blocking.

Browser checks use a synthetic five-second 48 kHz loop: corrected source attack at 0.35 s, 0.8–0.9 s uncertainty, explicit Add and Overwrite, saved-label reopening, 120→240 BPM recut with fixed 0.1 s beat one and unchanged attack times, and Undo. These are workflow checks, not acoustic accuracy, calibrated output or physical-device gesture validation. Native plugin code is unchanged.
