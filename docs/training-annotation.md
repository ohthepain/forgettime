# Recorded bar training annotation

Open **Training**, import a sample there or select the current retained take, then choose **Annotate training attacks**. Practice retains recording and bar review; import, detection tuning and training annotation are on Training. Entry stops replay/capture and disarms Auto before opening the editor. Recording, source replacement and simulation are unavailable while editing; Close annotation and in-app navigation offer Save draft, Discard and Stay for unsaved edits. Save draft stores labels and tempo in sessionStorage under the exact source/reference/bar identity, without changing the authoritative dataset. Reopening restores the draft for review; Add/Overwrite commits it, while Discard removes it. Storage failures keep the editor open. Browser reload/tab close uses the standard unsaved-work prompt; there are no automatic draft checkpoints.

1. Desired attacks are edited directly on the waveform. A new draft is seeded once from calculated hits; saved annotations take precedence. Green markers are desired; dashed blue markers are calculated. Hover or focus a desired marker to expose its top-right delete square, even when an audio region is selected. Click the waveform to add a missing attack; dragging selects audio or zooms without adding attacks. Focused-marker arrows and the middle left/right controls seek the next zero crossing. Drag the middle handle to move an attack directly.
2. **Mark uncertainty** is optional. It adds nonoverlapping half-open source ranges, with editable start/end seconds and removal. Desired markers remain stored inside uncertainty, but appear subdued and are excluded by the authoritative scorer. Undo restores marker, range, reset and tempo edits, with up to 100 steps.
3. **Save** is available directly beside Mark uncertainty, including from attack correction. These are tools, not required sequential steps. It displays desired source times and uncertain ranges. Add/Overwrite explicitly confirms review of every attack, including outside uncertain regions; there is no separate checkbox. Partial bars remain inspectable/editable but cannot be submitted. Entirely uncertain examples can be stored for inspection; `trainingEligible` excludes them from optimization.

Training tempo is separate from the original take and future live tempo. Changes keep beat one and every underlying marker at its source frame, recutting the bar bounds. Markers outside the new bar remain in the draft, so expanding/undoing restores them; saved examples include only labels within the selected available bar. Tempo persists while navigating training bars. Changed bounds have a new identity and Add preserves the previously saved example. A known matching identity requires explicit Overwrite; an example added in another window is never silently overwritten.

The detail waveform and overview use the import inspection controls: drag vertically on the detail to zoom time around the starting position; drag horizontally on the overview to navigate, or vertically on the overview to change waveform height. The overview shows the selected bar and highlights the visible passage. There are no separate zoom buttons. With either display focused, + and - zoom time and 0 resets the view. The focused overview uses left/right and Home/End for navigation, and up/down for waveform height. Dragging or cancelling a gesture never places or selects an attack. All view controls affect display only. Hovering or focusing a desired or calculated marker exposes the same square play control as import inspection. Marker playback runs to the next desired attack or the end of the available bar, even if that endpoint is outside the zoomed view. A horizontal drag on the detail waveform selects complete attack slices in either direction; the square play control plays this range. Selecting a desired attack clears the playback selection. Playback selection is temporary and creates neither desired attacks nor uncertain regions. Cancelled or multiple-pointer gestures cannot place attacks. The square play button uses `AudioRegionPreview` for one-shot original PCM from the selected attack or playback selection. Stop/Escape, selection/view/settings changes, hiding, navigation and unmount release output. There is no microphone input, scoring, normalization or altered PCM in audition. The reusable `src/components/WaveformDisplay.tsx` owns detail/overview rendering, navigation, selection, hover/focus, gestures and playback for both annotation and import inspection. Callers supply source-frame markers and domain edit callbacks; the display does not detect attacks, change the musical reference or save annotations.

The controller (`src/audio/training-annotation.ts`) converts capture clocks to frame zero of the retained full source by subtracting `audio.startFrame`. It hashes and owns the full mono PCM, uses source/bar IDs and the atomic training repository, preserves existing recording-group assignments, and creates new groups as unassigned. Source audio is deduplicated by canonical checksum. Cropped/saved/captured material conservatively declares unavailable source-edge context; an ordinary complete decoded import declares its own beginning/end available. No discarded ancestor audio is invented. Matching stored source metadata wins.

Overwrite replaces only current annotations/review status under the loaded fingerprint. Quota, validation or concurrent-change failures preserve the draft and prior committed dataset. There is no annotation revision history, automatic export or upload. Original take PCM, settings, reference and analysis remain untouched. Calculation changes update the overlay only; Reset desired attacks from detections requires confirmation and can be undone. The Training page reuses this editor for saved examples. Its comparison view supports the current or selected optimized profile; annotation calculation continues to use the review detector, with saved desired labels taking precedence.

## Verification

Controller tests cover source-clock conversion, tempo recuts/Undo, uncertainty validation, explicit reset, reviewed silence, full-source deduplication, overwrite, atomic failure retention, stale writes and partial rejection. Component tests exercise real fields/buttons, marker keyboard controls, explicit placement/movement suppression, ranges, detector changes, Save/Discard/Stay, failed save/retry and audition cleanup. Practice integration checks stop-before-entry and source-replacement blocking.

Browser checks use a synthetic five-second 48 kHz loop: corrected source attack at 0.35 s, 0.8–0.9 s uncertainty, explicit Add and Overwrite, saved-label reopening, 120→240 BPM recut with fixed 0.1 s beat one and unchanged attack times, and Undo. These are workflow checks, not acoustic accuracy, calibrated output or physical-device gesture validation. Native plugin code is unchanged.

The green bar pills in the overview select a bar for editing; unsaved annotations use the same navigation guard as Previous/Next. Save is disabled for incomplete bars. A previously saved bar offers **Exclude training bar**, which removes that example from the local training dataset while keeping shared source audio used by other examples. If a tempo recut makes the selected bar incomplete, exclusion still removes its saved example. The retained recording and editable annotations remain available to redo and save the bar later. Failed or conflicting removals leave the saved example intact.

Data lists one row per included source file with its saved bar count. Selecting a file opens its desired/calculated-hit comparison; **+** opens the separate audio picker for a new working sample. File headings show the filename and either **New** or a green included check. The file trash action atomically removes all examples for that source and prunes its unused PCM; failures and fingerprint conflicts leave the dataset intact. The imported working take is retained independently so it can be annotated again.

New samples added through Data open directly in annotation, using the filename tempo hint (or the current tempo) and beat one at decoded source frame zero. No reference-confirmation or annotation-launch step is required. **Tempo** and **Beat one (seconds)** are editable alongside the waveform; the beat-one marker is visible in the detail and overview. Arrow keys on the marker move it by one source frame (Shift: 1 ms). Changing beat one recuts bars without moving desired attacks and carries that reference into subsequent bar selections. Matching `.forget` pairs retain their saved reference; unreadable/mismatched metadata still requires the explicit audio-only fallback.


The bar start is always available as an audition slice, including source frame zero. Clicking outside the waveform clears its selected audio region. Space starts or restarts the entire visible detail passage, including from focused playback controls; editable fields and modal dialogs retain their normal keys. Escape or the playback stop button stops output. Playback cursors in the detail and overview follow Web Audio's playback clock; animation callbacks only repaint their position. Desired attacks expose a middle drag handle and previous/next zero-crossing controls, independent of the selected playback region. These edits never modify source PCM or calculated detector output.

Opening a bar seeds a clean editing baseline, whether or not the bar has been saved. Navigation prompts only after user edits to a complete bar. Bar pills are red when their exact source/bar identity is absent from the dataset and green when it is saved; saving or excluding updates the pills immediately in the editor.

Browser sample selection accepts batches. New source audio is decoded sequentially and retained as unannotated **New** files, within a shared 100-source / 256 MiB budget. The first new sample opens in annotation; other new samples can be selected from the file list after closing the editor. Included files show green checkmarks. Source checksums identify duplicates against both saved training sources and unsaved files already loaded; renamed copies are skipped and reported only in the completion popup. File errors are reported separately without discarding other successful imports. Imported batch files are retained in a separate on-device catalog across page reloads, independently of training inclusion. Optional `.forget` files in a batch are paired by filename stem.

The overview viewport moves independently of the selected training bar. Dragging or clicking the overview changes the visible source passage; only bar pills or Previous/Next change the current bar. The viewport has a yellow translucent area and outline, while the current bar's waveform is brighter in both detail and overview. Panning outside the current bar does not move or add its annotations.

The imported-file catalog uses atomic IndexedDB writes and restores with the microphone off. A file can be listed without any authoritative training examples; its New badge becomes an included check only when at least one bar is saved into training.

After batch import finishes, a modal lists the filenames of all skipped duplicates. Duplicates never add file-list entries; closing the popup leaves the file list unchanged.
