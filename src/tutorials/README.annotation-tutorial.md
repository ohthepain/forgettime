# Recorded bar annotation walkthrough

Launch `pnpm dev`, then open http://localhost:3030/annotation-tutorial (use the server's printed port if 3030 is occupied). This is one development-only walkthrough, served by the `dev-annotation-tutorial` middleware in `vite.config.ts`. It is not a production route or a design variant.

Question: can a user correct desired source-time attacks, mark uncertainty and safely Add/Overwrite a Recorded bar?

The actual `TrainingAnnotationEditor` runs with a synthetic four-second 48 kHz drum loop. Initial tutorial labels deliberately include an undesired 1.00 s point and omit an audible 1.25 s attack. Calculated markers still come from the production detector. The tutorial repository uses the production validation and compare-and-swap service in a separate worker with a temporary memory backend. No Window exists in that worker, so tutorial writes cannot send dataset-change broadcasts to real app windows. No actual training IndexedDB, saved bars, latest-take recovery, accounts, microphone or native plugin is read or written.

Sixteen steps cover opening, selecting/removing, precise insertion, Undo, tempo recutting, uncertainty, review, Add, Overwrite and unsaved Stay. Steps wait indefinitely until the user acts. Each step requires a new trusted editor interaction plus a fresh false-to-true completion transition before automatic advancement. Background rendering and repository notifications cannot arm a step. There is no timed advancement or automatic scrolling. Manual Next, Skip and Confirm remain available. Closing removes observation/listeners; reopening or revisiting an already-satisfied step explains the state and leaves it unverified until a fresh action or explicit verdict. Back/Next do not undo editor actions or fabricate evidence. Skip, Not working and Confirm retain distinct outcomes. Restart terminates the owned worker, resets all tutorial data/progress and returns to the introduction; it cannot revert real data.

The guide is portaled outside the app's animated/transformed shell, so fixed highlights, arrows and controls use the viewport clock/coordinates. The panel can be dragged by its header with mouse or touch; a compact colorful arrow bounces beside the target (respecting reduced motion). Target highlights reposition on resize/scroll/layout changes, with reachable navigation, keyboard focus and off-screen target recovery. Missing targets remove the arrow and give recovery instructions. Show target scrolls/focuses the real control. Copy report includes the question, scope, context, instructions, expectations, outcomes and limitations, with selectable text regardless of clipboard permission. No report is automatically saved or submitted; tutorial completion is not issue acceptance.

Verified in the actual browser: end-to-end correction → Undo → tempo → region → Add → sample nudge/Overwrite → unsaved Stay; The original version recorded 14 observed steps and two explicit confirmations; progression now requires a fresh user interaction on each step. Also exercised Back/Next, failure, skip, Restart after saved changes, Close/Reopen with actions while closed, already-satisfied conditions, missing-stage recovery, keyboard navigation, scrolling and 393×852 layout (document width 393, one panel within viewport, navigation reachable). A guide anchoring issue was repaired during verification; native accessibility snapshots were stale during some checks, so final checks used the live browser DOM. Physical touch, acoustically judged accuracy, capture-to-review entry and real durable storage are not tutorial evidence.

Remove the `dev-annotation-tutorial` plugin and its `readFileSync` import from `vite.config.ts`, and delete these four clearly named tutorial files plus this README, to remove the experience. Production editor/repository code is unchanged. Tutorial work is left uncommitted; no issue status, verdict, publication or deployment is changed.

## Load a sample guide

Open `/annotation-tutorial?sample=1` for seven steps over the actual PracticeScreen and import controls. The user chooses their own audio, tempo and beat-one reference. It uses normal on-device app recovery/preferences, and can replace the latest working take when the user confirms import. No automatic file selection, capture, training save or export. Restart resets only the guide, preserving real app data; use Import audio again to repeat. Paired metadata may bypass setup; explicit confirmation supports that path. Tempo and beat-one correctness are human judgments.

## Playback and selection guide

Open `/annotation-tutorial?playback=1` for seven steps covering marker hover/focus, bounded marker playback, horizontal region selection, selection playback and Stop/Escape. It uses the real editor with the isolated synthetic fixture. Dedicated target attributes distinguish the waveform, markers, playback controls and selection; user pointer/focus events can complete the hover step. Playback state is observed separately from pressing Play. Natural completion alone does not verify the Stop step. Restart resets only the tutorial fixture and progress.

## Splice file → saved training bar → comparison

Open `http://localhost:3030/?tutorial=splice` with `pnpm dev` running. This dev-only guide starts on Home, guides navigation to Training, then uses its importer and annotation controls, and uses the user's downloaded WAV/M4A. It never imports, edits labels or saves examples automatically. Value steps wait for Return/blur with valid input; audible-hit correctness and final comparison require an explicit verdict. Correction and save apply to one selected bar. Restart resets guide progress only and preserves app data. Reports are copy-only and exclude source filenames, PCM and labels. The removable integration is `src/tutorials/splice-training-guide.tsx`, the opt-in import in `DevFeedback`, its scoped CSS, and dedicated app identification attributes.

## Independent repro recorder

Open `/training?repro=1` to collect the reported “training waveform disappears after import” issue. Start recording begins an in-memory journal; demonstrate the issue, choose Bug reproduced, edit Expected/Actual/Notes, then Copy repro steps. Restart clears the journal and records from the current route. Same-document navigation retains the opt-in and ordered log; full reload clears the log. Add `&tutorial=splice` to run the guide independently alongside it. Recorder and tutorial controls are excluded from capture. No file-writing service, storage, upload or automatic fix is involved. Code: `src/dev/repro-steps.tsx` and `repro-journal.ts`; `/__repro-test` is a dev-only disposable controls page. Unit tests simulate event semantics in jsdom and must not be described as observed browser reproduction.

## Optimizer profile adoption guide

Launch `/?tutorial=profile` in development. This real-app guide starts at Home and walks through Training, selecting a completed saved run, reviewing scores, freezing its best candidate, explicit withheld evaluation, profile selection and dataset comparison. Users perform all profile-changing actions. The guide never starts a search, freezes/evaluates a candidate or adopts a profile automatically. Current-detector profiles also apply to Practice review; mel profiles are comparison-only and live microphone capture retains shared defaults. Restart resets guide state while preserving actual app changes.
